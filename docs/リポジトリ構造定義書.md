# ヘルプステーション シフト管理・予約管理システム リポジトリ構造定義書

- 作成日: 2026-09-11
- 前提資料: [要件定義書](./要件定義書.md)、[基本設計書](./基本設計書.md)、[技術仕様書](./技術仕様書.md)
- ステータス: ドラフト（レビュー前）

本書は、技術仕様書1章で決定した技術スタック（PHP 8.3 / Laravel 11、Inertia.js v2 + Vue.js 3、MySQL 8.0）を前提に、実装時のリポジトリのディレクトリ構成・命名規則・Git運用ルールを定めるものである。

## 1. ルートディレクトリ構成

Laravel標準構成をベースとし、本プロジェクト固有のディレクトリのみ以下に補足する。

```
helpstation/
├─ app/
│   ├─ Console/Commands/       バッチ処理（2.1参照）
│   ├─ Http/
│   │   ├─ Controllers/        画面・操作ごとのコントローラー（2.2参照）
│   │   ├─ Middleware/         認証・権限チェック等
│   │   └─ Requests/           フォームバリデーション（画面・操作ごとに1クラス）
│   ├─ Models/                 Eloquentモデル（2.3参照）
│   ├─ Policies/               シフト・予約の編集・削除における「自分のものか」の判定（2.7参照）
│   └─ Services/                業務ロジック（2.4参照）
├─ config/                     Laravel標準設定（logging.php にauditチャンネルを追加、2.5参照）
├─ database/
│   ├─ factories/              テスト用データファクトリ
│   ├─ migrations/             物理DB定義（技術仕様書4章に対応、マイグレーションファイル単位でテーブルを作成）
│   └─ seeders/                初期データ（支援内容・車両の初期マスタ等、技術仕様書4.6・4.7参照）
├─ docs/                       要件定義書・基本設計書・技術仕様書・本書
├─ resources/
│   ├─ css/                    Tailwind CSSエントリポイント
│   └─ js/
│       ├─ Components/         画面共通で使うUIパーツ（ボタン、モーダル、カレンダー等）
│       ├─ Layouts/            共通レイアウト（ヘッダー・ナビゲーション等）
│       └─ Pages/              Inertiaページ（2.6参照。基本設計書2章の画面一覧に1対1対応）
├─ routes/
│   ├─ console.php             タスクスケジューラ定義（予約忘れ検知等）
│   └─ web.php                 画面・操作のルーティング
├─ storage/
│   └─ logs/audit/              監査ログ出力先（技術仕様書5.3参照、Git管理対象外）

├─ package.json / package-lock.json
```

### 1.1 Git管理対象外とするもの

`.gitignore`に以下を含める。

- `.env`（DB接続情報・アプリケーションキー等の秘匿情報）
- `storage/logs/`（監査ログ・アプリケーションログ。本番環境のみに存在する運用データ）
- `vendor/`・`node_modules/`（Composer／npmの依存パッケージ）
- `public/build/`（`npm run build`で生成されるフロントエンドの成果物）

## 2. 主要ディレクトリの詳細

### 2.1 app/Console/Commands/

| ファイル | 内容 |
|---|---|
| `DetectMissedBookings.php` | 予約忘れ検知バッチ（技術仕様書5.2参照）。毎日1回`routes/console.php`のスケジューラから実行 |

### 2.2 app/Http/Controllers/

画面・機能ごとに1コントローラーとする。基本設計書2章の画面一覧（1〜9）に対応。

| コントローラー | 対応画面 |
|---|---|
| `AuthController` | 1. ログイン画面 |
| `ReservationController` | 2. 予約一覧画面、3. 予約申請フォーム（空き日時検索を含む） |
| `ShiftController` | 4. シフト申請フォーム |
| `ApprovalController` | 5. 承認画面（シフト・予約共通） |
| `StaffController` | 6. 職員マスタ（削除済み一覧・復元を含む） |
| `ClientController` | 7. 利用者マスタ（同上） |
| `SupportTypeController` | 8. 支援内容マスタ（同上） |
| `VehicleController` | 9. 車両マスタ（同上） |

マスタ系4コントローラーは、一覧・登録・変更・削除・削除済み一覧・復元の操作を共通の構造で持つため、共通処理は`App\Http\Controllers\Concerns\HasSoftDeletableMaster`（トレイト）に切り出す。

### 2.3 app/Models/

技術仕様書4章の物理設計に対応するEloquentモデル。

| モデル | テーブル |
|---|---|
| `Staff` | staff |
| `StaffDefaultSchedule` | staff_default_schedules |
| `Client` | clients |
| `SupportType` | support_types |
| `Vehicle` | vehicles |
| `Shift` | shifts |
| `ShiftDetail` | shift_details |
| `Reservation` | reservations |

`Staff`・`Client`・`SupportType`・`Vehicle`の4モデルには`Illuminate\Database\Eloquent\SoftDeletes`トレイトを付与する（要件定義書8.1項目26・34参照）。中間テーブル（`client_default_staff`、`client_fixed_days_of_week`、`reservation_staff`）はモデルクラスを持たず、Eloquentのリレーション定義（`belongsToMany`等）経由で扱う。

### 2.4 app/Services/

複数のコントローラーやモデルにまたがる業務ロジックを集約する。

| サービスクラス | 内容 |
|---|---|
| `VehicleAssignmentService` | 配車優先度・車両空き判定（技術仕様書5.1参照） |
| `MissedBookingDetectionService` | 予約忘れ検知ロジック（技術仕様書5.2参照。`DetectMissedBookings`コマンドから呼び出す） |
| `AuditLogger` | 監査ログ出力（技術仕様書5.3参照。登録・変更・削除・承認の各処理末尾で共通に呼び出す） |

### 2.5 config/logging.php

`audit`チャンネルを追加し、`storage/logs/audit/audit-YYYY-MM-DD.log`へ出力する（技術仕様書5.3参照）。`days`は1500程度に設定する。

### 2.6 resources/js/Pages/

基本設計書2章の画面一覧・技術仕様書7章のルーティングに1対1対応させる。

| ディレクトリ | 主なファイル |
|---|---|
| `Auth/` | `Login.vue` |
| `Reservations/` | `Index.vue`（予約一覧）、`Create.vue`（予約申請フォーム＋空き日時検索タブ） |
| `Shifts/` | `Form.vue` |
| `Approvals/` | `Index.vue` |
| `Masters/` | `Staff.vue`、`Clients.vue`、`SupportTypes.vue`、`Vehicles.vue`（いずれも有効一覧／削除済み一覧の切替タブを持つ） |

### 2.7 app/Policies/

権限制御は2種類に分ける（技術仕様書6章参照）。

- ルート単位の粗い制御（承認画面・マスタ管理等、管理者専用の画面・操作全体）：`app/Http/Middleware/`で`role`が`admin`かどうかを判定する。
- レコード単位の所有者判定（シフトの編集で「対象が自分のものか」を1件ごとに判定する必要がある操作）：`ShiftPolicy`で判定し、コントローラーから`$this->authorize()`を呼び出す（職員は自分のシフトのみ編集可、管理者は全件可）。予約の編集・削除は職員には行わせず管理者のみ可能なため、`ReservationPolicy`は所有者に関わらず管理者判定のみを行う。

| ファイル | 内容 |
|---|---|
| `ShiftPolicy.php` | `update`：`shift.staff_id === auth()->id()` または管理者なら許可 |
| `ReservationPolicy.php` | `update`・`delete`：管理者のみ許可（一般職員による確定済み予約の直接編集・削除は6.8参照の通り管理者のみのため） |

## 4. 命名規則

| 対象 | 規則 | 例 |
|---|---|---|
| PHPクラス（Model・Controller・Service） | UpperCamelCase、単数形（Modelは特に） | `Reservation`, `VehicleAssignmentService` |
| データベーステーブル | snake_case、複数形 | `reservations`, `support_types` |
| データベースカラム | snake_case | `dispatch_priority`, `deleted_at` |
| ルート（URI） | ケバブケース、複数形リソース名 | `/support-types`, `/reservations/available-slots` |
| Vueコンポーネント・ページ | UpperCamelCase（`.vue`） | `Create.vue`, `SupportTypes.vue` |
| Blade/Vueのprops・変数（JS側） | camelCase | `dispatchPriority` |
| Gitブランチ | `feature/`, `fix/`, `docs/` + 短い説明（kebab-case） | `feature/vehicle-assignment-service` |

## 5. Git運用ルール

- `main`ブランチを常にデプロイ可能な状態に保つ。
- 作業は`main`から派生した作業ブランチ（`feature/*`・`fix/*`等）で行い、Pull Requestを経て`main`へマージする（本ドキュメント群のこれまでの運用と同様）。
- コミットメッセージは変更内容を要約する1行＋必要に応じた詳細本文とする。
- マイグレーションファイルは一度`main`にマージした後は原則として編集せず、変更が必要な場合は新しいマイグレーションを追加する。
