# ヘルプステーション シフト管理・予約管理システム 環境構築手順書

- 作成日: 2026-09-15
- 前提資料: [技術仕様書](./技術仕様書.md)（1章の技術スタックを前提とする）、[CLAUDE.md](../CLAUDE.md)（開発環境・サーバーに必要な環境の一覧）
- ステータス: 実行順に並び替え（2026-09-18）

本書は、環境ごとの構築手順を、実際に実行する順番でまとめたものである。サーバーに必要な環境の一覧は CLAUDE.md を参照。

- **テストサーバー**：Ubuntu（自前サーバー）。以下「1. テストサーバー環境構築」を参照。
- **開発環境**：Windows（各開発者のPC）。WSL2上にUbuntuを導入して構築する（下記「2. 開発環境構築」参照）。
- **本番環境**：Xserver（共有ホスティング、root権限なし）。テストサーバー・開発環境とは別物で、デプロイ手順も異なる（下記「3. 本番環境（Xserver）へのデプロイ手順」参照）。

テストサーバー・開発環境はどちらもUbuntu上に同じソフトウェア（PHP 8.5.9・Composer 2.10.3・Node.js 24系・MariaDB 10.11・Git）を導入する。パッケージ導入・インストール確認のコマンドは「1. テストサーバー環境構築」側に記載し、「2. 開発環境構築」側は同じ内容を参照する形にして重複を避けている。

## 1. テストサーバー環境構築（Ubuntu）

### 1.1 前提

- OS：Ubuntu 26.04 LTSを想定する。他のディストリビューションの場合はパッケージ名・導入方法を読み替える。
- サーバーは開発者2名（山本・奥野）で共用し、各自が個別のSSHユーザーで接続する。
- サーバーは社内に設置し、Tailscaleに参加済みである。奥野は社外から接続するため、SSH・サーバーへのアクセスは（社内LANからの直接アクセスではなく）Tailscale経由を前提とする。ルーターのポートフォワーディングは行わない。

### 1.2 手順

#### 1.2.1 SSHユーザー作成

```bash
sudo adduser yamamoto
sudo adduser okuno
# 各自 ~/.ssh/authorized_keys に公開鍵を登録
```

「1.2.2 パッケージ導入」はOS全体に対する一度きりの作業のため、sudo権限を持つどちらか一方の開発者が1回だけ実行すればよい（2人分繰り返す必要はない）。「1.2.4 リポジトリのセットアップ」以降は、各開発者が自分のユーザーでSSH接続し、自分のホームディレクトリで個別に実行する。

#### 1.2.2 パッケージ導入

```bash
# パッケージ更新
sudo apt update && sudo apt upgrade -y

# PHP 8.5.9（ピンポイント指定）＋拡張機能（Ubuntu標準リポジトリにない場合はppa:ondrej/phpを追加）
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update

# 8.5.9の正確なパッケージバージョン文字列を確認する（例：8.5.9-1+ubuntu26.04.1+deb.sury.org+1）
apt-cache madison php8.5 | grep 8.5.9
# ↑で表示された「バージョン」列の文字列を、以下の <VERSION> に置き換えて実行する
sudo apt install -y php8.5=<VERSION> php8.5-cli=<VERSION> php8.5-fpm=<VERSION> php8.5-mbstring=<VERSION> \
  php8.5-xml=<VERSION> php8.5-curl=<VERSION> php8.5-zip=<VERSION> php8.5-mysql=<VERSION> \
  php8.5-bcmath=<VERSION> php8.5-gd=<VERSION> php8.5-intl=<VERSION>

# apt upgrade等で意図せず8.5.9からバージョンがずれないよう固定する
sudo apt-mark hold php8.5 php8.5-cli php8.5-fpm php8.5-mbstring php8.5-xml php8.5-curl php8.5-zip \
  php8.5-mysql php8.5-bcmath php8.5-gd php8.5-intl

# 既に8.5.9以外のバージョン（例：8.5.10）が入ってしまっている場合は、
# 一度 apt-mark unhold してから上記の apt install =<VERSION> を再実行するとダウングレードできる
# sudo apt-mark unhold php8.5 php8.5-cli php8.5-fpm php8.5-mbstring php8.5-xml php8.5-curl php8.5-zip \
#   php8.5-mysql php8.5-bcmath php8.5-gd php8.5-intl

# Composer（2.10.3を指定してインストール）
curl -sS https://getcomposer.org/installer | php -- --version=2.10.3
sudo mv composer.phar /usr/local/bin/composer

# Node.js 24系（LTS）
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt install -y nodejs

# MariaDB 10.11系（Ubuntu標準リポジトリからインストール）
sudo apt install -y mariadb-server
sudo mysql_secure_installation

# Git
sudo apt install -y git
```

#### 1.2.3 インストール確認

導入したバージョンが想定通りか、以下のコマンドで確認する。

| コマンド | 対象 | 想定バージョン |
|---|---|---|
| `php -v` | PHP | 8.5.9 |
| `composer --version` | Composer | 2.10.3 |
| `node -v` | Node.js | 24系 |
| `npm -v` | npm | Node.js 24系に同梱のバージョン |
| `mysql --version` | MariaDB | 10.11系 |
| `git --version` | Git | 最新版 |

#### 1.2.4 リポジトリのセットアップ

```bash
git clone <repo-url>
cd helpstation
composer install
npm install
cp .env.example .env
php artisan key:generate

# DB作成・.env設定・マイグレーション（DBスキーマ名は1.3のアクセス方法の表を参照）
mysql -u root -p -e "CREATE DATABASE <DB名>;"
# .envのDB_DATABASEを設定してから
php artisan migrate --seed
```

プロジェクト作成後は、以下でLaravelのバージョンも確認できる。

```bash
php artisan --version
```

想定バージョン：Laravel 13

#### 1.2.5 ポート開放

`<割り当てポート>`は、1.3の表にある自分のポート番号（山本：8001、奥野：8002）に置き換えること。

```bash
# tailscale0インターフェース限定。ルーターのポート開放は不要
sudo ufw allow in on tailscale0 to any port <割り当てポート> proto tcp
```

#### 1.2.6 開発サーバー起動

`<割り当てポート>`は、1.2.5と同じ自分のポート番号に置き換えること。

```bash
# --hostを明示しないとサーバー自身からしかアクセスできない点に注意
php artisan serve --host=0.0.0.0 --port=<割り当てポート>
npm run dev
```

### 1.3 アクセス方法

- サーバー上で `tailscale ip -4` を実行し、サーバーのTailscale IPを確認する。
- 各開発者は自分のPCのブラウザから `http://<サーバーのTailscale IP>:<自分のポート番号>` にアクセスする。

| 開発者 | DBスキーマ | ポート |
|---|---|---|
| 山本 | `helpstation_dev_yamamoto` | 8001 |
| 奥野 | `helpstation_dev_okuno` | 8002 |

### 1.4 補足

- `.env` は開発者ごとに用意し、Git管理対象外とする（リポジトリ構造定義書1.1参照）。
- 同一サーバー上で2名が同時にアクセスするため、作業ディレクトリ・DBスキーマ・`php artisan serve`使用時のポート番号は開発者ごとに分け、衝突を避ける（割り当ては上表の通り）。
- ポート開放は`ufw`を`tailscale0`インターフェースに限定することで、Tailscaleに参加していない第三者からのアクセスを防ぐ。

## 2. 開発環境構築（Windows・WSL2）

WSL2（Windows Subsystem for Linux 2）上にUbuntu 26.04を導入する。PC1台＝開発者1人のため、テストサーバー向けの手順にあるSSHユーザーの分離・Tailscale経由アクセス・ポート開放（`ufw`）は不要。

### 2.1 前提

- Windows 10（バージョン2004以降）またはWindows 11
- WSL2上でUbuntu 26.04を使用する
- CPUの仮想化機能（Intel VT-x／AMD-V）がBIOS/UEFIで有効になっていること（WSL2は仮想マシンの仕組みを利用するため必須。無効のままだとインストールコマンドが正常に完了せず、`wsl -l -v`にディストリビューションが表示されない）

### 2.2 インストール前の確認：仮想化の有効化

1. タスクマネージャー（`Ctrl+Shift+Esc`）→「パフォーマンス」タブ→「CPU」を選択し、右下の「仮想化」が「有効」になっているか確認する
2. 「無効」の場合、PCを再起動してBIOS/UEFI設定に入り（メーカーにより起動直後の`F2`・`F10`・`Del`・`Esc`等のキー）、「Advanced」等のメニューから以下を有効にする
   - Intel製CPUの場合：`Intel Virtualization Technology`（`Intel VT-x`）
   - AMD製CPUの場合：`SVM Mode`
3. 設定を保存して再起動し（多くの場合`F10`）、タスクマネージャーで「仮想化：有効」になったことを再確認してから、以下のインストール手順に進む

### 2.3 手順

#### 2.3.1 WSL2 + Ubuntuのインストール

```powershell
# PowerShellを管理者権限で実行
wsl --install -d Ubuntu-26.04
# インストール後、再起動を求められる場合がある。再起動しないとインストールが完了しない
```

```powershell
# インストール確認（再起動後、PowerShellで実行）
wsl -l -v
# 一覧に Ubuntu-26.04 が表示され、STATEが Stopped または Running であればインストール成功。
# 何も表示されない場合は、再起動が済んでいるか確認したうえで上記コマンドを再実行する
```

初回起動時、WSL内Ubuntuのユーザー名・パスワードを設定する。以降はWSL内のUbuntuターミナルで実行する。

#### 2.3.2 パッケージ導入

「1.2.2 パッケージ導入」と同じコマンドを実行する。

#### 2.3.3 インストール確認

「1.2.3 インストール確認」と同じ内容で確認する。

#### 2.3.4 リポジトリのセットアップ

`/mnt/c/`配下ではなくWSL内のLinuxファイルシステム（例：`~/projects/`）に配置すること。

- **現在地の確認**：作業フォルダで`pwd`を実行し、`/home/<ユーザー名>/...`と表示されればLinux側（OK）。`/mnt/c/Users/...`と表示された場合はWindows側に置いてしまっている。
- **やり方**：`cd /mnt/c/...`のようにWindows側のフォルダへ移動せず、最初から自分のホームディレクトリ配下（`~/projects/`等）で`git clone`する。すでに`/mnt/c/`配下にクローン済みの場合は、Windowsのエクスプローラーで該当フォルダを削除してから、下記の手順でクローンし直す。
- **理由**：`/mnt/c/`はWindowsとLinuxの変換を挟むため、ファイルを大量に読み書きする処理（`composer install`等）が大幅に遅くなる。

```bash
# 現在地を確認する
pwd
# 結果が /mnt/c/... だった場合は、まずホームディレクトリへ移動する
cd ~

mkdir -p projects && cd projects
git clone <repo-url>
cd helpstation
composer install
npm install
cp .env.example .env
php artisan key:generate

# DB作成・.env設定・マイグレーション（DB名は例としてhelpstation_devとする）
mysql -u root -p -e "CREATE DATABASE helpstation_dev;"
# .envのDB_DATABASEを設定してから
php artisan migrate --seed
```

#### 2.3.5 開発サーバー起動

```bash
php artisan serve
npm run dev
```

### 2.4 エディタ連携

#### VS Codeの導入

- [公式サイト](https://code.visualstudio.com/)からWindows版インストーラーをダウンロードして実行するか、PowerShellで以下を実行する。
  ```powershell
  winget install Microsoft.VisualStudioCode
  ```

#### WSL2との連携

1. VS Code（Windows側）の拡張機能タブから「WSL」（発行元：Microsoft、`ms-vscode-remote.remote-wsl`）をインストールする。
2. WSL内のUbuntuターミナルでプロジェクトフォルダに移動し、`code .` を実行する。初回はWSL側にVS Code Server（サーバーコンポーネント）が自動でインストールされる。
3. VS Codeが起動し、左下に緑色で `WSL: Ubuntu-26.04` と表示されていれば、WSL内のファイルに対して直接編集・ターミナル操作ができている状態。

#### PHP開発に必要な拡張機能

WSL連携後にインストールする拡張機能は、通知に従って「WSL: Ubuntu-26.04 にインストール」を選択すること（Windows側にだけ入れても、WSL側のPHP/Node環境に対しては機能しない）。

| 拡張機能 | 発行元／ID | 用途 |
|---|---|---|
| PHP Intelephense | `bmewburn.vscode-intelephense-client` | PHPのコード補完・定義ジャンプ・構文チェック |
| PHP Debug | `xdebug.php-debug` | Xdebugを使ったブレークポイントデバッグ |
| Laravel Extra Intellisense | `amiralizadeh9480.laravel-extra-intellisense` | ルート名・設定値等、Laravel固有の補完 |
| Vue - Official | `Vue.volar` | Vue 3（`<script setup>`）の構文・型サポート |
| Tailwind CSS IntelliSense | `bradlc.vscode-tailwindcss` | Tailwind CSSのクラス名補完 |
| ESLint | `dbaeumer.vscode-eslint` | JS/Vueのlint（開発ガイドライン1章の方針に対応） |
| Prettier - Code formatter | `esbenp.prettier-vscode` | JS/Vueのフォーマット（同上） |

### 2.5 アクセス方法

- WSL2はlocalhostの自動転送に対応しているため、WindowsのブラウザからそのままURL`http://localhost:8000`にアクセスできる。

### 2.6 補足

- Git用のSSH鍵は、WSL内のLinux環境に別途作成する（Windows側の鍵とは別）。
- テストサーバー向けの手順と異なり、SSHユーザー作成・Tailscale経由アクセス・ポート開放（`ufw`）の設定は不要（自分のPC上で完結するため）。

## 3. 本番環境（Xserver）へのデプロイ手順

Xserverの共有ホスティング（スタンダードプラン）はroot権限を持たず、**sudoコマンドは使用できない**。以下は全て、契約者用の一般ユーザー権限の範囲内で行う手順である。

### 3.1 前提

- サーバーパネルでPHPのバージョンを8.5系に設定済みであること
- サーバーパネルでMySQLデータベース・ユーザーを作成済みであること（ホスト名・DB名・ユーザー名・パスワードを控えておく）
- サーバーパネルでSSH接続情報（ホスト名・ユーザー名・ポート）を確認済みであること
- ドキュメントルートを、公開ドメイン配下のLaravelプロジェクト内`public/`ディレクトリに設定済みであること（サーバーパネルの「ドキュメントルート変更」機能。root権限は不要）

### 3.2 ビルド（ローカルまたはテストサーバーで実行）

Node.jsによるフロントエンドのビルドはXserver上では行わず、テストサーバーまたは開発環境（Windows・WSL2）で実行する（技術仕様書2章参照）。

```bash
composer install --no-dev --optimize-autoloader
npm install
npm run build
```

### 3.3 Xserverへのファイル転送

sudoを使わず、SSH経由のrsyncでファイルを転送する（FTPクライアントでも可）。

```bash
# ビルドした環境（ローカル）で実行。.git・.env・node_modulesは転送しない
rsync -avz --exclude='.git' --exclude='.env' --exclude='node_modules' \
  ./ <サーバーパネルで確認したユーザー名>@<サーバーパネルで確認したSSHホスト名>:~/<ドキュメントルート配下のパス>/
```

### 3.4 Composerの導入（Xserver上で直接`composer install`する場合）

3.2でローカル側に`vendor/`を含めて転送済みであれば本項は不要。Xserver上で直接installしたい場合は、root権限を使わず自分のホームディレクトリ配下にComposerを導入する。

```bash
# Xserverへ SSH 接続後（2.10.3を指定してインストール）
curl -sS https://getcomposer.org/installer | php -- --version=2.10.3
mkdir -p ~/bin
mv composer.phar ~/bin/composer
chmod +x ~/bin/composer
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

composer install --no-dev --optimize-autoloader
```

### 3.5 .env設定・キー生成

サーバーパネルで確認したMySQL接続情報を、Xserver上の`.env`に設定する。

```bash
# Xserver上で実行
cp .env.example .env
php artisan key:generate
```

```ini
DB_HOST=<サーバーパネルで確認したホスト名>
DB_DATABASE=<データベース名>
DB_USERNAME=<ユーザー名>
DB_PASSWORD=<パスワード>
```

### 3.6 マイグレーション・キャッシュ最適化

いずれもLaravel（`php artisan`）コマンドのみで完結し、sudoは不要。

```bash
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

### 3.7 バッチ処理（cron）の設定

サーバーパネルの「Cron設定」機能から登録する（root権限は不要、ユーザーレベルのcrontabとして動作する）。

```
* * * * * php /home/<ユーザー名>/<プロジェクトパス>/artisan schedule:run >> /dev/null 2>&1
```
