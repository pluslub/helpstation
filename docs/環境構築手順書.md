# ヘルプステーション シフト管理・予約管理システム 環境構築手順書

- 作成日: 2026-09-15
- 前提資料: [技術仕様書](./技術仕様書.md)（1章の技術スタックを前提とする）、[CLAUDE.md](../CLAUDE.md)（開発環境・サーバーに必要な環境の一覧）
- ステータス: 一次レビュー反映済み（2026-09-16）

本書は、環境ごとの構築手順をコマンド付きでまとめたものである。サーバーに必要な環境の一覧は CLAUDE.md を参照。

- **本番・テストサーバー**：Ubuntu（自前サーバー）。
- **開発環境**：Windows（各開発者のPC）。WSL2上にUbuntuを導入して構築する。

どちらもUbuntu上に同じソフトウェア（PHP 8.3系・Composer・Node.js 20系・MySQL 8.0・Git）を導入するため、共通する手順を「1. 共通手順」にまとめ、環境ごとに異なる部分（サーバーへの入り方、複数人共用のための設定等）のみ「2. 本番・テストサーバー固有の手順」「3. 開発環境固有の手順」に分けて記載する。

## 1. 共通手順（Ubuntu内で実行）

本番・テストサーバーではSSH接続後に、開発環境（Windows）ではWSL2内のUbuntuターミナルで、以下を実行する。

### 1.1 パッケージ導入

```bash
# パッケージ更新
sudo apt update && sudo apt upgrade -y

# PHP 8.3系＋拡張機能（Ubuntu標準リポジトリにない場合はppa:ondrej/phpを追加）
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update
sudo apt install -y php8.3 php8.3-cli php8.3-fpm php8.3-mbstring php8.3-xml \
  php8.3-curl php8.3-zip php8.3-mysql php8.3-bcmath php8.3-gd php8.3-intl

# Composer
curl -sS https://getcomposer.org/installer | php
sudo mv composer.phar /usr/local/bin/composer

# Node.js 20系（LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# MySQL 8.0
sudo apt install -y mysql-server
sudo mysql_secure_installation

# Git
sudo apt install -y git
```

### 1.2 リポジトリのセットアップ

開発環境（WSL2）の場合は、`/mnt/c/`配下ではなくWSL内のLinuxファイルシステム（例：`~/projects/`）に配置すること。

- **現在地の確認**：作業フォルダで`pwd`を実行し、`/home/<ユーザー名>/...`と表示されればLinux側（OK）。`/mnt/c/Users/...`と表示された場合はWindows側に置いてしまっているため、そのフォルダを削除し、`~/projects`配下に置き直す。
- **やり方**：WSL（Ubuntu）のターミナルで、`cd /mnt/c/...`のようにWindows側のフォルダへ移動せず、最初から自分のホームディレクトリ配下（`~/projects/`等）で`git clone`する。下記コマンドの通りに実行すればよい。
- **理由**：`/mnt/c/`はWindowsとLinuxの変換を挟むため、ファイルを大量に読み書きする処理（`composer install`等）が大幅に遅くなる。

```bash
# 現在地を確認する
pwd
# /mnt/c/... と表示された場合は、~/projects へ移動してから作業する
mkdir -p ~/projects && cd ~/projects

git clone <repo-url>
cd helpstation
composer install
npm install
cp .env.example .env
php artisan key:generate

# DB作成・.env設定・マイグレーション（DB名は環境ごとの節を参照）
mysql -u root -p -e "CREATE DATABASE <DB名>;"
# .envのDB_DATABASEを設定してから
php artisan migrate --seed
```

### 1.3 開発サーバー起動

起動コマンドは環境によって異なる（2・3章参照）。

- 本番・テストサーバー（複数人が共用し、外部からアクセスする）：`php artisan serve --host=0.0.0.0 --port=<割り当てポート>`
- 開発環境（Windows・WSL2、1人1台）：`php artisan serve`

いずれの場合も、あわせて `npm run dev` を実行する。

## 2. 本番・テストサーバー固有の手順（Ubuntu）

### 前提

- OS：Ubuntu 22.04 LTSを想定する。他のディストリビューションの場合はパッケージ名・導入方法を読み替える。
- サーバーは開発者2名（山本・奥野）で共用し、各自が個別のSSHユーザーで接続する。
- サーバーは社内に設置し、Tailscaleに参加済みである。奥野は社外から接続するため、SSH・サーバーへのアクセスは（社内LANからの直接アクセスではなく）Tailscale経由を前提とする。ルーターのポートフォワーディングは行わない。

### 手順

```bash
# 1. 開発者ごとのSSHユーザー作成・公開鍵登録
sudo adduser yamamoto
sudo adduser okuno
# 各自 ~/.ssh/authorized_keys に公開鍵を登録

# 2. 「1. 共通手順」を実行する（各開発者が自分のホームディレクトリで）

# 3. ポート開放（tailscale0インターフェース限定。ルーターのポート開放は不要）
sudo ufw allow in on tailscale0 to any port 8001 proto tcp

# 4. 開発サーバー起動（--hostを明示しないとサーバー自身からしかアクセスできない点に注意。ポートは開発者ごとに分ける）
php artisan serve --host=0.0.0.0 --port=8001
npm run dev
```

### アクセス方法

- サーバー上で `tailscale ip -4` を実行し、サーバーのTailscale IPを確認する。
- 各開発者は自分のPCのブラウザから `http://<サーバーのTailscale IP>:<自分のポート番号>` にアクセスする。

| 開発者 | DBスキーマ | ポート |
|---|---|---|
| 山本 | `helpstation_dev_yamamoto` | 8001 |
| 奥野 | `helpstation_dev_okuno` | 8002 |

### 補足

- `.env` は開発者ごとに用意し、Git管理対象外とする（リポジトリ構造定義書1.1参照）。
- 同一サーバー上で2名が同時にアクセスするため、作業ディレクトリ・DBスキーマ・`php artisan serve`使用時のポート番号は開発者ごとに分け、衝突を避ける（割り当ては上表の通り）。
- ポート開放は`ufw`を`tailscale0`インターフェースに限定することで、Tailscaleに参加していない第三者からのアクセスを防ぐ。

## 3. 開発環境固有の手順（Windows・WSL2）

WSL2（Windows Subsystem for Linux 2）上にUbuntu 22.04を導入する。PC1台＝開発者1人のため、本番・テストサーバー向けの手順にあるSSHユーザーの分離・Tailscale経由アクセス・ポート開放（`ufw`）は不要。

### 前提

- Windows 10（バージョン2004以降）またはWindows 11
- WSL2上でUbuntu 22.04を使用する
- CPUの仮想化機能（Intel VT-x／AMD-V）がBIOS/UEFIで有効になっていること（WSL2は仮想マシンの仕組みを利用するため必須。無効のままだとインストールコマンドが正常に完了せず、`wsl -l -v`にディストリビューションが表示されない）

### インストール前の確認：仮想化の有効化

1. タスクマネージャー（`Ctrl+Shift+Esc`）→「パフォーマンス」タブ→「CPU」を選択し、右下の「仮想化」が「有効」になっているか確認する
2. 「無効」の場合、PCを再起動してBIOS/UEFI設定に入り（メーカーにより起動直後の`F2`・`F10`・`Del`・`Esc`等のキー）、「Advanced」等のメニューから以下を有効にする
   - Intel製CPUの場合：`Intel Virtualization Technology`（`Intel VT-x`）
   - AMD製CPUの場合：`SVM Mode`
3. 設定を保存して再起動し（多くの場合`F10`）、タスクマネージャーで「仮想化：有効」になったことを再確認してから、以下のインストール手順に進む

### 手順

```powershell
# 1. WSL2 + Ubuntu 22.04のインストール（PowerShellを管理者権限で実行）
wsl --install -d Ubuntu-22.04
# インストール後、再起動を求められる場合がある。再起動しないとインストールが完了しない

# 2. インストール確認（再起動後、PowerShellで実行）
wsl -l -v
# 一覧に Ubuntu-22.04 が表示され、STATEが Stopped または Running であればインストール成功。
# 何も表示されない場合は、再起動が済んでいるか確認したうえで手順1を再実行する

# 3. 初回起動時、WSL内Ubuntuのユーザー名・パスワードを設定する
```

以降はWSL内のUbuntuターミナルで、「1. 共通手順」を実行する。DB名は例として`helpstation_dev`とする。最後に以下で開発サーバーを起動する。

```bash
php artisan serve
npm run dev
```

### エディタ連携

#### VS Codeの導入

- [公式サイト](https://code.visualstudio.com/)からWindows版インストーラーをダウンロードして実行するか、PowerShellで以下を実行する。
  ```powershell
  winget install Microsoft.VisualStudioCode
  ```

#### WSL2との連携

1. VS Code（Windows側）の拡張機能タブから「WSL」（発行元：Microsoft、`ms-vscode-remote.remote-wsl`）をインストールする。
2. WSL内のUbuntuターミナルでプロジェクトフォルダに移動し、`code .` を実行する。初回はWSL側にVS Code Server（サーバーコンポーネント）が自動でインストールされる。
3. VS Codeが起動し、左下に緑色で `WSL: Ubuntu-22.04` と表示されていれば、WSL内のファイルに対して直接編集・ターミナル操作ができている状態。

#### PHP開発に必要な拡張機能

WSL連携後にインストールする拡張機能は、通知に従って「WSL: Ubuntu-22.04 にインストール」を選択すること（Windows側にだけ入れても、WSL側のPHP/Node環境に対しては機能しない）。

| 拡張機能 | 発行元／ID | 用途 |
|---|---|---|
| PHP Intelephense | `bmewburn.vscode-intelephense-client` | PHPのコード補完・定義ジャンプ・構文チェック |
| PHP Debug | `xdebug.php-debug` | Xdebugを使ったブレークポイントデバッグ |
| Laravel Extra Intellisense | `amiralizadeh9480.laravel-extra-intellisense` | ルート名・設定値等、Laravel固有の補完 |
| Vue - Official | `Vue.volar` | Vue 3（`<script setup>`）の構文・型サポート |
| Tailwind CSS IntelliSense | `bradlc.vscode-tailwindcss` | Tailwind CSSのクラス名補完 |
| ESLint | `dbaeumer.vscode-eslint` | JS/Vueのlint（開発ガイドライン1章の方針に対応） |
| Prettier - Code formatter | `esbenp.prettier-vscode` | JS/Vueのフォーマット（同上） |

### アクセス方法

- WSL2はlocalhostの自動転送に対応しているため、WindowsのブラウザからそのままURL`http://localhost:8000`にアクセスできる。

### 補足

- Git用のSSH鍵は、WSL内のLinux環境に別途作成する（Windows側の鍵とは別）。
- 本番・テストサーバー向けの手順と異なり、SSHユーザー作成・Tailscale経由アクセス・ポート開放（`ufw`）の設定は不要（自分のPC上で完結するため）。
