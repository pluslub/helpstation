- 作成日: 2026-09-15
- 前提資料: [技術仕様書](./技術仕様書.md)（1章の技術スタックを前提とする）、[CLAUDE.md](../CLAUDE.md)（開発環境・サーバーに必要な環境の一覧）
- ステータス: 一次レビュー反映済み（2026-09-16）

本書は、環境ごとの構築手順をコマンド付きでまとめたものである。サーバーに必要な環境の一覧は CLAUDE.md を参照。

- **本番・テストサーバー**：Ubuntu。以下「1. 本番・テストサーバー環境構築」を参照。
- **開発環境**：Windows（各開発者のPC）。WSL2上にUbuntuを導入して構築する（下記「2. 開発環境構築」参照）。

## 1. 本番・テストサーバー環境構築（Ubuntu）

### 前提

- OS：Ubuntu 22.04 LTSを想定する。他のディストリビューションの場合はパッケージ名・導入方法を読み替える。
- サーバーは開発者2名（山本・奥野）で共用し、各自が個別のSSHユーザーで接続する。
- サーバーは社内に設置し、Tailscaleに参加済みである。奥野は社外から接続するため、SSH・サーバーへのアクセスは（社内LANからの直接アクセスではなく）Tailscale経由を前提とする。ルーターのポートフォワーディングは行わない。

### 手順

```bash
# 1. パッケージ更新
sudo apt update && sudo apt upgrade -y

# 2. PHP 8.3系＋拡張機能（Ubuntu標準リポジトリにない場合はppa:ondrej/phpを追加）
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update
sudo apt install -y php8.3 php8.3-cli php8.3-fpm php8.3-mbstring php8.3-xml \
  php8.3-curl php8.3-zip php8.3-mysql php8.3-bcmath php8.3-gd php8.3-intl

# 3. Composer
curl -sS https://getcomposer.org/installer | php
sudo mv composer.phar /usr/local/bin/composer

# 4. Node.js 20系（LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 5. MySQL 8.0
sudo apt install -y mysql-server
sudo mysql_secure_installation

# 6. Git
sudo apt install -y git

# 7. 開発者ごとのSSHユーザー作成・公開鍵登録
sudo adduser yamamoto
sudo adduser okuno
# 各自 ~/.ssh/authorized_keys に公開鍵を登録

# 8. リポジトリのクローンと依存関係インストール（各開発者が自分のホームディレクトリで）
git clone <repo-url>
cd helpstation
composer install
npm install
cp .env.example .env
php artisan key:generate

# 9. 開発者ごとのDB作成・.env設定・マイグレーション
mysql -u root -p -e "CREATE DATABASE helpstation_dev_yamamoto;"
# .envのDB_DATABASEを自分のDB名に設定してから
php artisan migrate --seed

# 10. ポート開放（tailscale0インターフェース限定。ルーターのポート開放は不要）
sudo ufw allow in on tailscale0 to any port 8001 proto tcp

# 11. 開発サーバー起動（--hostを明示しないとサーバー自身からしかアクセスできない点に注意。ポートは開発者ごとに分ける）
php artisan serve --host=0.0.0.0 --port=8001
npm run dev
```

### アクセス方法

- サーバー上で `tailscale ip -4` を実行し、サーバーのTailscale IPを確認する。
- 各開発者は自分のPCのブラウザから `http://<サーバーのTailscale IP>:<自分のポート番号>` にアクセスする。

| 開発者 | DBスキーマ | ポート |
|---|---|---|
| 山本 | `helpstation_dev_yamamoto` | 8001 |
| 奥野 | `helpstation_dev_okuno` | 8002 |

### 補足

- `.env` は開発者ごとに用意し、Git管理対象外とする（リポジトリ構造定義書1.1参照）。
- 同一サーバー上で2名が同時にアクセスするため、作業ディレクトリ・DBスキーマ・`php artisan serve`使用時のポート番号は開発者ごとに分け、衝突を避ける（割り当ては上表の通り）。
- ポート開放は`ufw`を`tailscale0`インターフェースに限定することで、Tailscaleに参加していない第三者からのアクセスを防ぐ。

## 2. 開発環境構築（Windows・WSL2）

WSL2（Windows Subsystem for Linux 2）上にUbuntu 22.04を導入し、本番・テストサーバーとほぼ同じ手順で構築する。PC1台＝開発者1人のため、本番・テストサーバー向けの手順にあるSSHユーザーの分離・Tailscale経由アクセス・ポート開放（`ufw`）は不要。

### 前提

- Windows 10（バージョン2004以降）またはWindows 11
- WSL2上でUbuntu 22.04を使用する

### 手順

```powershell
# 1. WSL2 + Ubuntu 22.04のインストール（PowerShellを管理者権限で実行）
wsl --install -d Ubuntu-22.04
# インストール後、再起動を求められる場合がある

# 2. 初回起動時、WSL内Ubuntuのユーザー名・パスワードを設定する
```

以降はWSL内のUbuntuターミナルで実行する。

```bash
# 3. パッケージ更新
sudo apt update && sudo apt upgrade -y

# 4. PHP 8.3系＋拡張機能
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update
sudo apt install -y php8.3 php8.3-cli php8.3-fpm php8.3-mbstring php8.3-xml \
  php8.3-curl php8.3-zip php8.3-mysql php8.3-bcmath php8.3-gd php8.3-intl

# 5. Composer
curl -sS https://getcomposer.org/installer | php
sudo mv composer.phar /usr/local/bin/composer

# 6. Node.js 20系（LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 7. MySQL 8.0
sudo apt install -y mysql-server
sudo mysql_secure_installation

# 8. Git
sudo apt install -y git

# 9. リポジトリのクローンと依存関係インストール
# WSL内のLinuxファイルシステム上に配置すること（/mnt/c/配下に置くと動作が大きく遅くなるため避ける）
mkdir -p ~/projects && cd ~/projects
git clone <repo-url>
cd helpstation
composer install
npm install
cp .env.example .env
php artisan key:generate

# 10. DB作成・.env設定・マイグレーション
mysql -u root -p -e "CREATE DATABASE helpstation_dev;"
# .envのDB_DATABASEを設定してから
php artisan migrate --seed

# 11. 開発サーバー起動
php artisan serve
npm run dev
```

### エディタ連携

- VS Codeの「WSL」拡張機能を使うと、WindowsのVS CodeからWSL内のファイルを直接編集・ターミナル操作できる（WSL内のプロジェクトフォルダで`code .`を実行）。

### アクセス方法

- WSL2はlocalhostの自動転送に対応しているため、WindowsのブラウザからそのままURL`http://localhost:8000`にアクセスできる。

### 補足

- Git用のSSH鍵は、WSL内のLinux環境に別途作成する（Windows側の鍵とは別）。
- 本番・テストサーバー向けの手順と異なり、SSHユーザー作成・Tailscale経由アクセス・ポート開放（`ufw`）の設定は不要（自分のPC上で完結するため）。
