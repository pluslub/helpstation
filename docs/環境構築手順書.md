テストサーバー・開発環境はどちらもUbuntu上に同じソフトウェア（PHP 8.5系・Composer 2.10.3・Node.js 24系・MariaDB 10.11.19・Git）を導入する。パッケージ導入・インストール確認のコマンドは「1. テストサーバー環境構築」側に記載し、「2. 開発環境構築」側は同じ内容を参照する形にして重複を避けている。

## 1. テストサーバー環境構築（Ubuntu）

### 1.1 前提

- OS：Ubuntu 24.04 LTSを想定する。他のディストリビューションの場合はパッケージ名・導入方法を読み替える。（Xserver（本番）のDBがMariaDB 10.11系固定であり、10.11.19はUbuntu 26.04向けには提供されていないが24.04向けには提供されているため、24.04を採用している）
- サーバーは開発者2名（山本・奥野）で共用し、各自が個別のSSHユーザーで接続する。
- サーバーは社内に設置し、Tailscaleに参加済みである。奥野は社外から接続するため、SSH・サーバーへのアクセスは（社内LANからの直接アクセスではなく）Tailscale経由を前提とする。ルーターのポートフォワーディングは行わない。

### 1.2 手順

#### 1.2.1 SSHユーザー作成

```bash
sudo adduser yamamoto
```

```bash

```

各自`~/.ssh/authorized_keys`に公開鍵を登録する。

#### 1.2.2 パッケージ導入

パッケージ一覧を更新する。

```bash
sudo apt update && sudo apt upgrade -y
```

**PHP 8.5系のインストール**：Ubuntu 24.04（noble）標準リポジトリにはPHP 8.5系が存在しないため、`ppa:ondrej/php`を追加する（このPPAはUbuntu 26.04「resolute」向けには提供されていないが、24.04「noble」では利用できることを確認済み）。

`packages.sury.org`（`ppa:ondrej/php`の将来的な統合先として案内されている）も試したが、noble向けに提供されているバージョン（`8.5.10-1+0~20260828.25+ubuntu24.04~1.gbpfea0b8`）はバージョン文字列に`~`（スナップショット版を示す記号）を含み、`ppa:ondrej/php`提供版より低いものとして扱われ、既存インストール済みパッケージへの適用が「ダウングレード」としてエラーになった。そのため現時点では`ppa:ondrej/php`を採用する。

```bash
sudo add-apt-repository ppa:ondrej/php -y
```

```bash
sudo apt update
```

正確なパッケージバージョン文字列を確認する（sury.org側の更新により随時変わるため、下記のバージョンで見つからない場合はこのコマンドで再確認し、手順書のバージョン文字列を更新する）。

```bash
apt-cache madison php8.5
```

バージョン文字列は`8.5.10-1+ubuntu24.04.1+deb.sury.org+1`で確認済み（2026-09-18時点）。`php8.5-common`・`php8.5-readline`も依存関係上必要なため、同じバージョンで合わせて指定する。既に別バージョンでhold済みの場合は`--allow-change-held-packages`を付ける。

```bash
sudo apt install -y --allow-change-held-packages php8.5=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-common=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-cli=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-fpm=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-readline=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-mbstring=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-xml=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-curl=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-zip=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-mysql=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-bcmath=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-gd=8.5.10-1+ubuntu24.04.1+deb.sury.org+1 php8.5-intl=8.5.10-1+ubuntu24.04.1+deb.sury.org+1
```

apt upgrade等で意図せずバージョンがずれないよう固定する。

```bash
sudo apt-mark hold php8.5 php8.5-common php8.5-cli php8.5-fpm php8.5-readline php8.5-mbstring php8.5-xml php8.5-curl php8.5-zip php8.5-mysql php8.5-bcmath php8.5-gd php8.5-intl
```


```bash

```

```bash

```

```bash
sudo apt-mark hold mariadb-server
```

```bash
sudo mariadb-secure-installation
```

対話式で以下の質問が順に表示される。このプロジェクトでの推奨回答は以下の通り。

| 質問 | 意味 | 推奨回答 |
|---|---|---|
| `Enter current password for root (enter for none)` | 現在のrootパスワード入力（新規インストール直後は未設定） | そのまま**Enter**（何も入力しない） |
| `Switch to unix_socket authentication [Y/n]` | rootログインを、パスワードではなくOSのユーザー名で認証する方式に切り替えるか | **`n`**（下記【重要】参照） |
| `Change the root password? [Y/n]` | rootパスワードを設定するか | **`Y`**として、山本・奥野の2人がわかる共通パスワードを設定する |
| `Remove anonymous users? [Y/n]` | 匿名ユーザー（ユーザー名なしでログインできる初期アカウント）を削除するか | **`Y`** |
| `Disallow root login remotely?` | rootのリモート（他ホストから）ログインを禁止するか | **`Y`**（サーバー上から`mysql -u root -p`で使うだけなので問題なし） |
| `Remove test database and access to it?` | 初期状態で用意されている`test`データベースを削除するか | **`Y`** |
| `Reload privilege tables now?` | ここまでの変更を即時反映するか | **`Y`** |

**【重要】`unix_socket`認証について**：ここで`Y`を選ぶと、rootへのログインが「Linux上でrootユーザーとしてログインしている場合のみ」許可される方式に変わり、パスワードでのログインができなくなる。山本さん・奥野さんはどちらも一般ユーザー（sudo権限はあるがrootそのものではない）でSSH接続するため、`Y`にすると1.2.4の`mysql -u root -p -e "CREATE DATABASE <DB名>;"`が使えなくなる（`sudo mysql`のような書き換えが必要になる）。手順書の記載をそのまま使えるように、**ここは`n`を選んで、パスワード認証のままにしておく**こと。

`Change the root password?`で設定したパスワードは、山本さんとも共有しておくこと（お二人ともこのrootアカウントで共有のDBスキーマ`helpstation_tna`にアクセスする想定のため）。

#### 1.2.5 ポート開放

`<割り当てポート>`は、1.3の表にある自分のポート番号（山本：8001、奥野：8002）に置き換えること。tailscale0インターフェース限定であり、ルーターのポート開放は不要。

| 開発者 | ポート |
|---|---|

### 1.4 補足

- `.env` は開発者ごとに用意し、Git管理対象外とする（リポジトリ構造定義書1.1参照）。DB接続情報（`DB_DATABASE=helpstation_tna`等）は共通だが、`APP_URL`等は各自の値を設定する。
- 同一サーバー上で2名が同時にアクセスするため、作業ディレクトリ・`php artisan serve`使用時のポート番号は開発者ごとに分け、衝突を避ける（割り当ては上表の通り）。
- DBスキーマ`helpstation_tna`は開発者ごとに分けず共有する。そのため、一方が実行したマイグレーション・投入したテストデータはもう一方にも反映される（意図的な運用）。
- ポート開放は`ufw`を`tailscale0`インターフェースに限定することで、Tailscaleに参加していない第三者からのアクセスを防ぐ。

## 2. 開発環境構築（Windows・WSL2）

WSL2（Windows Subsystem for Linux 2）上にUbuntu 24.04を導入する。PC1台＝開発者1人のため、テストサーバー向けの手順にあるSSHユーザーの分離・Tailscale経由アクセス・ポート開放（`ufw`）は不要。

### 2.1 前提

- Windows 10（バージョン2004以降）またはWindows 11
- WSL2上でUbuntu 24.04を使用する
- CPUの仮想化機能（Intel VT-x／AMD-V）がBIOS/UEFIで有効になっていること（WSL2は仮想マシンの仕組みを利用するため必須。無効のままだとインストールコマンドが正常に完了せず、`wsl -l -v`にディストリビューションが表示されない）

### 2.2 インストール前の確認：仮想化の有効化

1. タスクマネージャー（`Ctrl+Shift+Esc`）→「パフォーマンス」タブ→「CPU」を選択し、右下の「仮想化」が「有効」になっているか確認する
2. 「無効」の場合、PCを再起動してBIOS/UEFI設定に入り（メーカーにより起動直後の`F2`・`F10`・`Del`・`Esc`等のキー）、「Advanced」等のメニューから以下を有効にする
   - Intel製CPUの場合：`Intel Virtualization Technology`（`Intel VT-x`）
   - AMD製CPUの場合：`SVM Mode`
3. 設定を保存して再起動し（多くの場合`F10`）、タスクマネージャーで「仮想化：有効」になったことを再確認してから、以下のインストール手順に進む

### 2.3 手順

#### 2.3.1 WSL2 + Ubuntuのインストール

PowerShellを管理者権限で実行する。

```powershell
wsl --install -d Ubuntu-24.04
```

インストール後、再起動を求められる場合がある。再起動しないとインストールが完了しない。

インストール確認（再起動後、PowerShellで実行する）。

```powershell
wsl -l -v
```

一覧に`Ubuntu-24.04`が表示され、STATEが`Stopped`または`Running`であればインストール成功。何も表示されない場合は、再起動が済んでいるか確認したうえで上記コマンドを再実行する。

初回起動時、WSL内Ubuntuのユーザー名・パスワードを設定する。以降はWSL内のUbuntuターミナルで実行する。

#### 2.3.2 パッケージ導入

「1.2.2 パッケージ導入」と同じコマンドを実行する。

#### 2.3.3 インストール確認

「1.2.3 インストール確認」と同じ内容で確認する。

#### 2.3.4 リポジトリのセットアップ

`/mnt/c/`配下ではなくWSL内のLinuxファイルシステム（例：`~/projects/`）に配置すること。

- **現在地の確認**：作業フォルダで`pwd`を実行し、`/home/<ユーザー名>/...`と表示されればLinux側（OK）。`/mnt/c/Users/...`と表示された場合はWindows側に置いてしまっている。
- **やり方**：`cd /mnt/c/...`のようにWindows側のフォルダへ移動せず、最初から自分のホームディレクトリ配下（`~/projects/`等）で`git clone`する。すでに`/mnt/c/`配下にクローン済みの場合は、Windowsのエクスプローラーで該当フォルダを削除してから、下記の手順でクローンし直す。
- **理由**：`/mnt/c/`はWindowsとLinuxの変換を挟むため、ファイルを大量に読み書きする処理（`composer install`等）が大幅に遅くなる。

現在地を確認する。

```bash

```

```bash

```

```bash

```

```bash

```

```bash

```

```bash

```

## 3. 本番環境（Xserver）へのデプロイ手順

Xserverの共有ホスティング（スタンダードプラン）はroot権限を持たず、**sudoコマンドは使用できない**。以下は全て、契約者用の一般ユーザー権限の範囲内で行う手順である。

### 3.1 前提

- サーバーパネルでPHPのバージョンを8.5.9に設定済みであること
- サーバーパネルでMySQLデータベース・ユーザーを作成済みであること（ホスト名・DB名・ユーザー名・パスワードを控えておく）
- サーバーパネルでSSH接続情報（ホスト名・ユーザー名・ポート）を確認済みであること
- ドキュメントルートを、公開ドメイン配下のLaravelプロジェクト内`public/`ディレクトリに設定済みであること（サーバーパネルの「ドキュメントルート変更」機能。root権限は不要）

### 3.2 ビルド（ローカルまたはテストサーバーで実行）

Node.jsによるフロントエンドのビルドはXserver上では行わず、テストサーバーまたは開発環境（Windows・WSL2）で実行する（技術仕様書2章参照）。

```bash
composer install --no-dev --optimize-autoloader
```

```bash
npm install
```

```bash
npm run build
```

### 3.3 Xserverへのファイル転送

sudoを使わず、SSH経由のrsyncでファイルを転送する（FTPクライアントでも可）。ビルドした環境（ローカル）で実行する。`.git`・`.env`・`node_modules`は転送しない。

```bash
rsync -avz --exclude='.git' --exclude='.env' --exclude='node_modules' ./ <サーバーパネルで確認したユーザー名>@<サーバーパネルで確認したSSHホスト名>:~/<ドキュメントルート配下のパス>/
```

### 3.4 Composerの導入（Xserver上で直接`composer install`する場合）

3.2でローカル側に`vendor/`を含めて転送済みであれば本項は不要。Xserver上で直接installしたい場合は、root権限を使わず自分のホームディレクトリ配下にComposerを導入する。Xserverへ SSH 接続後、以下を実行する（2.10.3を指定してインストール）。

```bash
curl -sS https://getcomposer.org/installer | php -- --version=2.10.3
```

```bash
mkdir -p ~/bin
```

```bash
mv composer.phar ~/bin/composer
```

```bash
chmod +x ~/bin/composer
```

```bash
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
```

```bash
source ~/.bashrc
```

```bash
composer install --no-dev --optimize-autoloader
```

### 3.5 .env設定・キー生成

サーバーパネルで確認したMySQL接続情報を、Xserver上の`.env`に設定する。Xserver上で実行する。

```bash
cp .env.example .env
```

```bash
php artisan key:generate
```

```ini
DB_HOST=<サーバーパネルで確認したホスト名>
DB_DATABASE=<データベース名>
DB_USERNAME=<ユーザー名>
DB_PASSWORD=<パスワード>
```


```bash

```



### 3.7 バッチ処理（cron）の設定

サーバーパネルの「Cron設定」機能から登録する（root権限は不要、ユーザーレベルのcrontabとして動作する）。

```
* * * * * php /home/<ユーザー名>/<プロジェクトパス>/artisan schedule:run >> /dev/null 2>&1
```
